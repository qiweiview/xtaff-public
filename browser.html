Browser bridge for AI coding agents

Your agent works in the browser you are already in.

Xtaff Browser connects Claude Code, Codex, Cursor or any other MCP client to your real Chrome — your tabs, your sessions, your logins — and asks you before an agent touches a new site.

The problem: agents cannot see your browser

A coding agent can read your files and run commands, but the page you are looking at — the logged-in admin panel, the internal tool, the checkout you are debugging — is outside its reach. The usual workarounds each cost something:

How it works

  1. The extension executes. It runs inside your Chrome, owns a tab group, and performs clicks, typing, navigation and reads only after the origin is approved.
  2. The host connects. A small native host on your machine bridges the extension to the MCP server over native messaging. It is registered once with xtaff-browser-host.
  3. The server exposes tools. xtaff-browser-mcp gives the agent 41 tools over stdio or HTTP, and returns screenshots, page structure, network records and script results.

What it adds beyond a plain bridge

One tab group per MCP connection

Each connection gets its own Xtaff·<name> group. Tab IDs, element refs, batches, scripts, uploads, downloads, sessions and takeovers from another group are rejected at the extension, not merely filtered in the server. You can stop one agent by group and keep the others running.

Per-site approval by default

A site the agent has not been granted opens as a blank tab with a prompt. Nothing loads until you allow that origin. Stopping, taking over and resuming are all in the popup, with a badge and a desktop notification when the agent is waiting.

Site playbooks, including your own walkthroughs

An agent can save how a site behaves and other local agents can search that knowledge later. You can also record a walkthrough in the popup; the draft covers HTTP/HTTPS pages, up to 20 steps, and does not store typed text or sensitive field values until you review and publish it.

Saved sessions and account switching

Capture the cookies and localStorage of a signed-in tab as a named profile, then apply it to switch accounts. Credentials stay in the session store; the model context only sees the profile name and the resulting page.

Remote use over HTTP and a tunnel

Run the server in HTTP mode behind your own tunnel to drive a browser on another machine — for example, the always-on office computer from home. HTTP mode has no TLS of its own and is meant for loopback or a tunnel, never a public port.

Also in the 41 tools: batched steps (up to 50), a restricted scripting tool for loops and branches, console and network inspection with redacted bodies, screenshots with password masking, file upload up to 10 MB and download capture, and explicit human takeover with human_required.

Boundaries — what it does not do

  • Not a CI or parallel automation tool. It drives the browser you use; for clean repeatable runs in CI, use Playwright.
  • No hosted or cloud browser. Remote use needs your own tunnel, and HTTP mode is unencrypted.
  • Desktop Chrome only. Not Firefox, Safari or Chrome for Android.
  • Human steps stay human. Sign-in, CAPTCHA, MFA and payments are handed back to you.
  • What the agent reads leaves through your client. Your MCP client sends it to the model provider configured there; that is the client's data path, not Xtaff's.

Frequently asked

What is Xtaff Browser?

Xtaff Browser is a Chrome extension plus a local MCP host. It lets an AI coding agent use the Chrome you are already signed in to, with per-site approval, instead of starting a separate browser.

How is it different from Playwright MCP or Chrome DevTools MCP?

Playwright MCP starts its own browser with a fresh profile, so your logins do not carry over. Chrome DevTools MCP attaches over the DevTools protocol, and since Chrome 136 the default profile refuses --remote-debugging-port. Xtaff Browser runs inside your existing Chrome through an extension and a local host.

Does my browsing data go to Xtaff?

No. The extension talks to a native host on your machine, not to a Xtaff service. What the agent reads is sent by your MCP client to the model provider configured there.

Can several agents use the same browser at once?

Yes. Each MCP connection gets its own tab group titled Xtaff·<name>, and tools in one group cannot see or act on tabs in another. Site approvals, logins and browser memory stay shared.

Which MCP clients are supported?

Any client that can run a local stdio server, such as Claude Code, Codex, Cursor or Zed. An HTTP mode is available for clients that connect over HTTP.

Does it work on Windows or Linux?

Not verified yet. The extension, host and server are built for desktop Chrome on macOS, Windows and Linux, but only macOS has been tested so far.

Can it operate an intranet system that needs a login?

Yes, as long as the site opens in your Chrome. Sign-in, CAPTCHA and MFA are handed back to you and the agent waits, then continues.

How do I uninstall it?

Run xtaff-browser-host --uninstall, then npm uninstall --global @xtaff/browser-mcp, and remove the extension from Chrome. See the install guide.

Xtaff Browser 是 Chrome 扩展 + 本机 MCP 宿主。它让 Claude Code、Codex、Cursor 等 AI 编程助手在你当前已登录的 Chrome 里操作网页：用你现成的标签页和登录态，默认按站点授权，而不是另起一个干净的浏览器。

和另外三条路线比

路线用现有登录态另起浏览器主要代价
Playwright / Puppeteer 自建浏览器否（默认新 profile）是要重新登录，SSO / MFA 通常过不去

在普通桥接之外

  • 每个 MCP 连接一个标签组：跨组的标签号、元素引用、批处理、脚本、上传下载、会话和接管都在扩展执行点被拒绝。
  • 默认逐站授权：未授权的站点先开空白标签并请求允许，允许前不加载目标页面。
  • 站点 Playbook：Agent 可保存站点经验供本机所有 Agent 检索；你也可以在弹窗里示教录制（仅 HTTP/HTTPS，最多 20 步，不记录输入文字和敏感字段值），编辑后再发布。
  • 会话存档：把已登录标签页的 Cookies 与 LocalStorage 存成具名档案，用来切换账号；凭据不进模型上下文。
  • 跨机使用：MCP 支持 HTTP 模式，配合你自己的隧道，用家里的 Agent 操作公司常开电脑上的浏览器。HTTP 本身不加密，只走回环或隧道。

边界

不是 CI 并行自动化工具（那边用 Playwright）；不做云端中转，也没有托管浏览器；仅桌面版 Chrome，不支持 Firefox / Safari / 安卓版 Chrome；登录、验证码、MFA、支付等仍由你本人完成；Agent 读到的内容会由它自己的 MCP 客户端发往所配置的模型服务。

常见问题

Xtaff Browser 是什么？
Xtaff Browser 是 Chrome 扩展 + 本机 MCP 宿主，让 AI 编程助手在你当前已登录的 Chrome 里操作网页，默认按站点授权，而不是另起一个干净的浏览器。

和 Playwright MCP、Chrome DevTools MCP 有什么区别？
Playwright 类方案另起浏览器、用新 profile，登录态带不过去；CDP 附加受 Chrome 136 起「默认 profile 不允许调试端口」的限制。Xtaff 通过扩展 + 本机宿主直接在你现有 Chrome 里执行。

支持 Windows 和 Linux 吗？
尚未验证。扩展、宿主和服务端按 macOS / Windows / Linux 桌面版 Chrome 设计，目前只实测了 macOS。

怎么卸载？
先运行 xtaff-browser-host --uninstall，再运行 npm uninstall --global @xtaff/browser-mcp，最后在 Chrome 里移除扩展。
